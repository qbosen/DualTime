# DualTime

[简体中文 README](README-cn.md)

DualTime is a native macOS menu bar app that shows a second clock using a configurable time zone. It keeps the system menu bar style and displays the configured time beside the system clock as closely as macOS allows.

The menu bar shows one configured time zone. Left click opens a live list of time zones, starting with Shanghai and Los Angeles. Time zones are stored as IANA identifiers, so daylight-saving rules and offset changes are handled by the system time-zone database.

## Features

- English: `Wed Oct 14 09:30`
- Chinese: `10月14日 周三 09:30`
- 24-hour time with optional seconds
- Optional date and weekday display
- Optional flashing time separators
  - Without seconds, the `HH:mm` separator flashes.
  - With seconds, `HH:mm` stays stable and only the `mm:ss` separator flashes.
- Fixed status-item width recalculated only when display settings or time zone change
- System San Francisco font with monospaced digits and right-aligned text
- Searchable IANA time zone list with common cities pinned first
- Automatic daylight-saving and UTC-offset handling
- English and Chinese UI through the centralized `Localizable.xcstrings` String Catalog
- Optional launch at login through `SMAppService`
- Accessory application that stays in the menu bar and does not appear in the Dock
- Left click shows only time-zone names, numeric dates, weekdays, and times; right click provides settings and quit
- Add, remove, and reorder time zones by dragging or using arrows
- Localized full city names, stable abbreviations such as SH/LOS, or custom names
- Independent list formatting: MM/DD, DD/MM, or YYYY-MM-DD; optional weekdays and seconds; 12/24-hour time
- Settings organized into Menu Bar, Time Zones, Behavior, and General tabs
- Hide the time panel immediately or after a delay when the pointer leaves, or choose Never; closing on outside clicks is configured separately

## Requirements

- macOS 14 or later
- Apple Silicon or Intel Mac
- Xcode 26 or later for the included project

## Build

```sh
xcodebuild -project DualTime.xcodeproj -scheme DualTime -configuration Release -sdk macosx -derivedDataPath .build-universal ONLY_ACTIVE_ARCH=NO CODE_SIGNING_ALLOWED=NO build
```

The local Universal 2 app, containing `arm64` and `x86_64` slices, is available at `dist/DualTime.app`. It is unsigned and intended for local use. The project includes a light, monochrome double-clock app icon in `DualTime/Assets.xcassets`.

## Tests

```sh
xcodebuild -project DualTime.xcodeproj -scheme DualTime -configuration Debug -sdk macosx -derivedDataPath .build-universal ONLY_ACTIVE_ARCH=NO CODE_SIGNING_ALLOWED=NO test
```

The menu bar is managed by macOS. The app uses a fixed-width status item, the system menu bar color, and the San Francisco system font with monospaced digits. Public APIs cannot guarantee a fixed position directly beside the system clock or force priority over other status items when space is unavailable. The app therefore requests the closest available position without private APIs.

The default display updates at the next minute boundary. Enabling seconds or flashing separators changes the refresh cadence to once per second. This only updates one lightweight status-item label and avoids unnecessary work in the default mode.

## Distribution and signing

The checked-in project builds an unsigned local `.app`. macOS may show a security prompt when opening an unsigned app downloaded or copied from another machine. Public distribution requires a Developer ID signing identity and notarization, which are intentionally not configured in this repository.

The repository does not commit `dist/DualTime.app`; the app is regenerated by the Release build command above. Build directories, Xcode user state, and Finder metadata are ignored by Git.

## Localization

User-interface text is centralized in `DualTime/Localizable.xcstrings`. SwiftUI views use localization keys directly, while AppKit menu items and window titles use the `L10n` helper. To add a language, add its translations to the String Catalog and add a case to `AppLanguage`; date formatting remains separate from interface translation.
